# 评审：关于"事中生成与事中监督"的那份分析

**日期**：2026-10-27
**对象**：内部讨论稿《两个场景与 GymMane 的范式差异》（下称"原文"）
**前提**：WhatGym 是新主体，在 GymMane 与 SportsHelper 的思想上再进一层，**不以 SportsHelper 为主体做增量**。
**结论**：原文把领域判断讲对了七八成，但它推荐的路线是"旧产品加一层传感器"。这条路对 WhatGym 是错的。真正的下一层不是更强的感知，是**可被复核的决策权**。

---

## 0. 三句话裁决

1. GymMane 记账，DongKe 排课并发口令，**WhatGym 判"继续 / 降级 / 停"，并为每个判断留证**。差别的落点是责任，不是精度。
2. 安全分级的分界线不是人群（程序员 / 老人），是**当次失效后果的可逆性**。矩阵的输入应是 `riskState`，不是 `userType`。
3. 核心时间抽象必须是 **Segment**，不是 Set。否则传统功法永远塞不进来——这条 DongKe 已经用一份 issue 否掉了。

## 1. 原文对的部分（可直接继承）

| 判断 | 为什么对 | 落到 WhatGym |
|---|---|---|
| 决策窗口从"下一次"压到"这一次" | 它解释了为什么"下周再调计划"不能承担安全责任 | 安全相关判断必须有 **当次** 出口，不能只留在 session 后 |

| 信号三：碎片完成率↑ 且代偿率不↑ | 全文最硬的一条——它是**可反驳的双指标**，单看任何一个都能自欺 | 作为首版唯一的成功判据 |
| Places 是生成约束而非筛选器 | 不新增功能，改变的是逻辑起点 | 器材/空间进决策上下文 |

另外一条原文没提、但值得继承的：DongKe 的 `ADR 0007`（一拍一句、预算按秒、超预算先丢「共 N 组」）已经把**节奏监督的话语句法学**趟过了。那是"什么时候该闭嘴"的模型，比任何语音反馈框架都具体。WhatGym 不该重新发明。

## 2. 原文错的地方（六条，都有依据）

### 2.1 事实过时：GymMane 不是当前主体，"事后记录"也不成立了

现在跑着的代码是 DongKe（native，SwiftData，零三方依赖），已经有：

- 组级三种状态（完成 / 跳过 / 跳过原因），`DongKeCore/Models/`
- 「这组做不动」三选降级：`DongKe/Features/Workout/WorkoutView.swift:442` / `:473`（`confirmationDialog`）
- 一整套播报闸门与话句预算：`docs/adr/0007-播报一套语义两个引擎.md`
- 30 分钟断点续练、组间休息状态机、每周排程

所以"事中"这件事已经发生了，**只是触发权在用户手里**——系统等用户点「做不动」，它自己不判断。

结论：原文建议的"第一步：增加监督事件实体"会做出一个与现有 `SetLog` 三态、播报闸门高度重叠的层。**真正的增量只有一处：系统主动触发**。把这条当成 WhatGym 的第一性差异，比"加实体"准确得多。

### 2.2 Tinetti 不能当入场闸门

原文把 "PAR-Q+ 与 Tinetti 并列，作为进入训练前的强制闸门"。这两者性质完全不同：

- **PAR-Q+** 是自填问卷，可以在 App 内做。
- **Tinetti** 是治疗师**施测**的平衡与步态量表，含坐站、转身、步态多个项目，需要现场、需要器械、需要评分者。

在 App 里"算"一个 Tinetti 分数，等于伪造测量。可做的替代只有三类：自报跌倒史/用药/眩晕、PAR-Q+、以及**可自我施测的代理指标**（30 秒坐站次数、5 次坐站用时）。把这个区分写死，否则安全内核从第一天就建在假数据上。

### 2.3 用人群做安全轴，是错的分类维度

原文给了"程序员矩阵"和"老人矩阵"两套。后果不对称的真正来源不是年龄，是**当次动作的失效代价**：

| 维度 | 低后果 | 高后果 |
|---|---|---|
| 支撑 | 双腿、有扶手 | 单腿、无支撑 |
| 位置 | 低位、贴近地面 | 高位、站立/台阶 |
| 速度 | 慢、可控 | 快速、爆发 |
| 载荷 | 自重 | 负重/弹力带远端 |

一个 30 岁程序员做保加利亚分腿蹲失衡会摔；一个常年练太极的 70 岁老人做坐站可能非常稳。按人群切会在两端同时出错：**劝退健康老人，漏掉高风险的年轻人**。

矩阵的键应是 `动作固有失效后果 × 当次可观测不稳定度 × 历史恢复证据`。人群只是先验起点，不是上限。

### 2.4 信号一的分母拿不到，且与隐私叙事自相矛盾

"高风险 rep 之前的拦截率"要求先有"高风险 rep"的 ground truth。居家场景里这个标签只能来自录像 + 人工标注——正好击穿"数据不出设备"。

可离线测的替代指标（不需要标注）：

- **推翻率**：24h 内用户撤销/推翻了系统决定的比例
- **次日回访率**：被降级/暂停之后，第二天还回来练的比例
- **「其实还能做」自报率**：组后一次点选，度量过度保守
- **组后不适率**：疼痛/眩晕/呼吸异常的自报

前两个度量"烦不烦"，后两个度量"保不保"。四个都是本地可算的。

### 2.5 "无摄像头也能估代偿"过于乐观

腕部 IMU 测不到膝内扣——那是额状面的事，腕部在矢状面运动链的末端。手机绑弹力带测到的是**拉力节奏**，不是关节对线。物理上只有**双侧 IMU + 已知器械几何**才勉强能推左右不对称。

没有视觉时能拿到的只有四件：节奏、幅度（相对自身基线）、左右时序差、停顿/放弃点。

这条必须写在能力边界里。否则会做出"看起来在监督、其实在猜"的功能——**比不监督更危险**，因为它消耗信任却不承担保护。

### 2.6 "身体数据从未离开设备"这句话目前不完全成立

DongKe 的计划生成走用户自填的 AI 端点（Keychain 存），档案与 brief 会发出去。所以那句话在"训练记录"层面成立，在"生成"层面不成立。

要用隐私当护城河，架构上得先做**双平面**：

- **本地平面**：记录、裁判、留证——永不出设备，断网可用
- **可外发平面**：计划生成——明确告知，可整机关闭

两平面不混，那句话才敢印在商店页上。

### 2.7 它默认"再深一层"必须长在旧产品上

原文第四步说"把降级和暂停设计为一等交互结果"。方向对，但**在一个已经冻结了"计划只由生成器产出"的产品里，裁判永远是外挂**——它只能在事后改下一份计划，改不了当下正在跑的那份。

这正是新主体的理由：裁判必须在核心循环里，而不是套在外面。你的判断比原文更对。

## 3. WhatGym 的骨架：三条结构性决定

### 决定一：产品对象是 Decision，不是 Rep

原文把"监督信号"和"决策响应"塞进同一个实体。这会让日志被高频信号淹没，无法审计。分成三层：

| 层 | 频率 | 稳定性 | 例 |
|---|---|---|---|
| **Signal** | 高（每 rep / 每秒） | 会随传感器换代全部作废 | 膝角速度、左右时序差、停顿 1.2s |
| **Observation** | 低（每组 / 每次） | 稳定 | 本次不稳定度、放弃点、疼痛自报 |
| **Decision** | 极稀（一次判断一条） | **长期资产** | 继续 / 降级 / 暂停 / 终止 / 转人工 |

**每条 Decision 必须自带凭据**：触发它的信号快照、规则与模型版本、当时的置信、用户的响应、事后的反馈。

这是 WhatGym 唯一在三年后还值钱的东西。因为无教练在场，产品的合法性不来自准确率，来自**可解释、可回放、可被第三方复核**。

一句话：**卖的不是智能，是敢负责。**

### 决定二：时间抽象是 Segment，不是 Set

`Segment = { 意图, 目标, 可观测约束, 结束条件 }`。Set 只是 Segment 的特例（有组次计数）。

- 抗阻：Segment = 3 组 × 12 次，约束是 RIR 2–3
- 功法：Segment = 一段 90 秒连续动作，约束是节律与换式点，**无组次**
- 碎片：Segment = 8 分钟循环，约束是"不换衣服、不出汗"

DongKe 的 `.scratch/follow-along/issues/01` 已经把"把功法塞进组次模型"判死，理由三条都成立：播报变噪音、完成率/降阶率口径被污染、体验上不像跟练。WhatGym 若用 Set 做主键，等于把那条死路继承过来。

### 决定三：安全矩阵的键是失效后果

三档，配三种交互：

| 档 | 条件 | 系统行为 | 留痕 |
|---|---|---|---|
| 低后果 | 双腿、有位、慢速 | 自动降级，**静默**，session 末告知 | 一条 Decision |
| 中后果 | 单腿或高位，当次尚稳 | 降级 + 一次确认 | Decision + 用户响应 |
| 高后果 | 高位/负重 + 不稳定 + 有疼痛或眩晕 | **立即暂停**，需显式确认才继续 | Decision + 不可忽略记录 |

人群只决定**默认起点**（老人默认从中后果起步），不决定上限。这条同时解决"劝退"和"漏报"。

## 4. 一条原文没提、但更早的岔路：零架设

原文把"姿态还是 IMU"推后了，说"不需要现在决定"。对，但还有一个**更早**的岔路它没指出：

> **产品是否要求用户改变物理环境？**

任何"把手机架起来、退到 3 米外、确保全身入画"的方案，在居家场景的首次成功率都很低——尤其老人，第一次失败就不会有第二次。这不是技术选型，是产品形态：

- **零架设可成立** → 形态是"无视觉裁判"：语音 + 触觉 + 自报 + 负荷/节奏自适应。能做的事很多，且今天就能做。
- **零架设不成立** → 第一版不是产品，是实验。实验可以，但别叫产品。

这个判断应该先于所有抽象。因为在它之上才有"能不能看见"的问题。

## 5. 下一步：三档，一周内都能出结论

### A. 本周可完成（不写 app 代码）

1. **《决策清单 v0》**：把"停 / 降 / 继续"的条件逐条写成可测试句。格式固定为
   `Given 信号 → When 阈值 → Then 决定 → 留什么证`。上限 20 条，目标是**可被教练挑错**，不是全。
2. **8–10 个轮转案例（tabletop）**：从最高后果的动作里挑（保加利亚分腿蹲、单腿硬拉、台阶、坐站、负重深蹲），写成"系统会怎么判 / 教练会怎么判"两列。这一步就能暴露矩阵的真假，成本一天。
3. **一句话合规边界**，写进 README 并约束之后所有文案：
   > 不筛查疾病，不做诊断，只在运动过程中做安全降级；出现红旗症状（胸痛、眩晕、意识模糊、突发无力）只做一件事——建议停止并就医。

### B. 需要一次外部验证（1–2 周）

4. **教练盲评**：2 位有老年训练经验的教练或治疗师，评你的 20 条规则而不是系统的输出。只问一句："你在现场会做同样的决定吗？" 不一致的条目就是规则要改的地方，也是下一步加深的精确靶点。比买传感器便宜两个数量级。
5. **30 秒坐站自测方差**：在真人身上跑 10 次，确认这个指标够稳到能当"剂量是否合适"的度量。不稳就换 5 次坐站用时。

### C. 第一版明确不做

- 不做姿态识别（在"零架设"没有答案之前）
- 不做功法内容（版权与持续供给是内容团队的事，不是代码）
- 不做云端裁判（可审计必须本地、可离线）
- 不做社交、排行榜、打卡分享

## 6. 这一步做完会得到什么

不是 app，是**一份能判生死的规格**：

- 若 20 条里有三分之一教练不同意 → "裁判"这个定位还太早，退回到"教练在场时的辅助"，先证明辅助有用。
- 若同意率高且集中在同一类分歧（例如疼痛主诉的处理）→ 方向成立，靶点明确，可以开始写第二个东西：`Decision` 的数据结构。

顺序上，**先加深判断标准，再选技术**。原文这句话是对的，我只是把它从"旧产品加一层"挪到"新产品定骨架"。
