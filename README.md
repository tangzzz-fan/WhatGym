# WhatGym

在 GymMane 与 SportsHelper 的思想上再进一层：**不只记账、不只排课，而是对"这一下要不要继续"作出判断，并为判断留证。**

## 与两个前身的关系

| | 定位 | 决策权 |
|---|---|---|
| GymMane | 事后记录（Flutter） | 用户持权，系统记账 |
| SportsHelper / DongKe | 事中排课 + 播报 + 用户主动降级（native） | 系统给计划，用户自报偏差 |
| **WhatGym** | 事中裁判：继续 / 降级 / 暂停 / 终止 | **系统持权，且必须留证** |

不是 SportsHelper 的功能分支。差别不在功能多少，在**谁有资格说停**。

## 三条骨架（待验证）

1. **产品对象是 Decision，不是 Rep。** Signal（高频、易过时）→ Observation（每组一次）→ Decision（极稀、长期资产）。每条 Decision 自带信号快照、规则版本、用户响应、事后反馈。
2. **时间抽象是 Segment，不是 Set。** 抗阻是一段有组次的 Segment，功法是一段无组次的 Segment。用 Set 做主键，功法永远进不来。
3. **安全分级的键是失效后果，不是人群。** 矩阵输入 `动作固有后果 × 当次不稳定度 × 历史恢复证据`；年龄只决定默认起点。

## 能力边界（约束所有文案）

> 不筛查疾病，不做诊断，只在运动过程中做安全降级。出现红旗症状（胸痛、眩晕、意识模糊、突发无力）只做一件事：建议停止并就医。

- 没有摄像头时，只能测节奏、幅度（相对自身基线）、左右时序差、停顿/放弃点。**测不到膝内扣等额状面代偿**——不假装能测。
- 记录与裁判全本地、可离线、可审计；计划生成可外发且明确告知。两个平面不混。
